# 架构与可维护性

检查职责、业务规则和文件如何组织，以及一次变更会影响哪些位置。优先关注核心流程、状态转换、持久化和外部副作用的边界，以及近期反复修改的规则。

## 检查重点

- 沿入口、调用链和数据流检查职责混杂、跨层访问内部状态，以及依赖关系造成的实际耦合。分析循环依赖时区分运行期、类型引用和延迟导入。
- 检查调用方为完成一个业务动作必须知道哪些内部状态、调用顺序、配置和错误处理细节。结合现有调用点，评估能否由职责所属处承担这些知识，缩小调用方需要理解的范围。
- 查找散落在核心流程中的易变业务规则，区分相似代码与同一知识的重复维护。核对按租户、地区或版本变化的行为是否被固定为统一逻辑，以及同一规则变化时是否必须同步修改多个职责。
- 选取已有业务变体、当前需求或近期实际变更，沿调用链列出需调整的接口、规则、映射和测试。比较现状与建议方案的修改牵连、理解成本和验证范围，也计入新接口、跨文件跳转和迁移成本。
- 评估职责调整、局部抽取或已有抽象能否减少隐式调用顺序和同步修改。设计模式按收益选用；扩展理由应有现有变体、明确需求或计划支撑。

## 判断边界

先识别架构文档中的明确约束，在约束内评估方案；现状描述与设计理由用于理解取舍。保留集中编排、单文件或现有分层时，仍可评估其内部的局部抽取、去重和接口收窄。

建议应落到具体职责和变更场景。若只是换目录、增加层次，调用方仍承担同样的知识，或拆分后需要传递大量共享状态，继续寻找更小的调整；收益不足时保留现状。

## 文件与目录组织

对于已有多个协作文件或明确扩展计划的重要特性，评估是否应集中到独立目录或 package，内部按职责命名，子领域形成后再增加层级。关注同一特性以 `feature_*.py` 等名称平铺、与无关代码混杂，造成定位和修改困难的情况。

简单、独立的小功能可以保留单文件。也检查层级过深、透传入口和同一职责过度碎片化的问题；共享前缀或文件数量只能作为线索。

建议归组或拆分时，说明职责边界和收益，必要时给目标目录树。涉及搬迁时提示需核对的导入、动态入口、资源路径或测试归属，不要求在检查阶段制定完整迁移方案。

## 规模参考

没有项目规模约定时，使用以下数值寻找值得深入阅读的位置：

| 对象 | 排查参考 |
| --- | --- |
| 文件 | 500 行供参考；超过 800 行分析，超过 1000 行重点分析 |
| 函数 | 超过 100 行分析，超过 200 行重点分析 |
| 嵌套 | 超过 3 层时检查各层是否必要 |

行数含 import、注释和声明，函数行数计入嵌套定义。结合业务逻辑、模型声明、测试或生成代码的性质评估，必要时区分主要篇幅。

超出数值只触发分析，不直接构成 finding。文件职责集中可以支持保留整体，也要检查局部规则是否重复、调用接口是否泄露细节。拆分后若仍需传递大量局部变量、整份对象或互调私有方法，应重新评估边界。

## 判断示例

- 场景：同一结算费率分别写在下单、退款和对账模块中，当前结果一致，最近的费率调整也正确修改了三处。判断：可报告规则归属的重构机会。现状需要三处解释同一规则；集中规则后，各模块保留自身流程，费率调整及规则验证可集中。需核对三处是否确实共享费率语义，并计入接口调整成本。
- 场景：协议规定帧头始终占用固定字节数，解析器直接使用该常量。判断：不因硬编码而报告。协议约束稳定，没有证据表明配置化能改善维护。
- 场景：架构约定订单流程集中编排，长文件中三个分支重复计算同一种状态转换条件，近期新增状态时均需修改。判断：保留集中编排，评估在文件内提取状态判断；收益是集中同一规则，停止点是消除重复解释，无需新建模块或改造分层。

### 同一特性的文件散落在上级目录

场景：报告导出已有 CSV、PDF 两种格式，PDF 还包含独立的排版逻辑。相关文件频繁一起修改，却与其他特性混在同一目录中：

```text
projects/
  report_export.py
  report_export_csv.py
  report_export_pdf.py
  report_export_pdf_layout.py
```

判断：可报告文件组织问题。结合导入关系，评估如下归组方式，让导出入口、格式实现和 PDF 内部逻辑的归属更容易定位：

```text
projects/
  report_export/
    export.py
    csv.py
    pdf/
      render.py
      layout.py
```

实际布局沿用项目命名与 package 约定。若只是一份独立的小型导出脚本，保留单文件即可。

### 长文件有合理的保留依据

场景：某文件超过 1000 行，大部分是同一协议的模型声明，没有混合业务流程；按版本拆开反而会让维护同一协议频繁跨文件跳转。

判断：需要重点分析，但不单凭行数报告问题。核对声明占比、职责和调用方后，若保留更利于维护，说明依据即可。
