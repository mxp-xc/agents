# 终态迁移与彻底清理

适用前提：允许代码与文档直接切到目标形态；若涉及存量数据，可在部署时一次性处理，或接受未处理数据回退/重置。需要零停机新旧版本混跑且不可回退的在线变更不适用。

## 步骤

1. 代码与文档直达最终形态
   迁移或改造代码（如 Python/SQL、schema、模型、接口、测试）时，直接按目标设计实现，不留旧版兼容分支、适配层、fallback 或读取时升级逻辑。README、注释与项目文档同步改写为当前现状，删除被替代的旧用法与过渡说明。
   完成标准：diff 仅包含目标形态的代码与文档；全局检索旧标识符、旧字段、旧表名与旧用法无残留。

2. 删改业务时沿引用链清理残留
   删除或下线某块业务时，沿调用链与引用关系向下排查，一并删除仅服务于该业务的函数、类、变量、类型/schema、SQL、配置项、测试与文档。无法 100% 确认是否仍有引用的项（如反射、动态导入、外部脚本或跨仓库调用）先保留，在最终回复中列出疑似残留清单及原因。
   完成标准：已确认无外部引用的关联代码与文档全部清理；存疑项已列入最终回复。

3. 仅涉及存量数据时，用临时脚本一次性处理
   脚本放 `temp/code/`，以直接够用、测试不影响业务为准；仅在数据量大或转换复杂时再补 `--dry-run` 或幂等保护。仅在本地开发库执行并验证业务正常，不直连共享或生产库。其余环境的迁移步骤与未执行后果写入任务单或 PR 正文；尚未创建任务单/PR 时，在最终回复中提供可直接粘贴的部署说明。
   完成标准：本地业务验证通过；其余环境有部署说明；脚本未进入版本控制（若目标仓库未忽略 `temp/`，用完即删），`git status` 与暂存区不包含该脚本。
